# CLAUDE.md

WorldEditor: a 3D world/map editor (WoW/WC3-editor style). Desktop app built with Wails v2 (Go) and a
Svelte 5 + TypeScript + Three.js frontend. It must stay **fast** and build on **Windows and Linux**.

## Commands

```bash
make dev             # wails dev -tags webkit2_41 (hot reload; browser debug at http://localhost:34115)
make build-linux     # wails build -tags webkit2_41  → build/bin/WorldEditor
make build-windows   # wails build -platform windows/amd64 → build/bin/WorldEditor.exe
make test            # go test ./internal/...
make check           # go vet + (cd frontend && pnpm check)
cd frontend && pnpm build   # frontend only
```

- Linux **requires** `-tags webkit2_41`. This system only has webkit2gtk-4.1.
- Package manager is **pnpm**. Don't add npm/yarn lockfiles.
- `go vet ./...` at the repo root fails if `frontend/dist` is missing (it's `//go:embed`ed). Build the
  frontend first, or vet `./internal/...` only.
- `frontend/wailsjs/` is generated by Wails from the bound Go methods. Never edit it by hand; it
  regenerates on `wails dev`/`wails build` (or `wails generate module -tags webkit2_41`).

## Architecture

- **Go owns file I/O only** (`app.go`: dialogs, `SaveMap`, `LoadMap`). Keep it thin. Everything about
  rendering and editing lives in the frontend.
- `internal/mapfile`: the `.wmap` format is gzip(magic "WMAP" + version + JSON header + raw height
  float32 + splatA + splatB). Blobs cross the bridge as base64 strings. If you change the format, bump
  `Version` and update the tests.
- **Engine** (`frontend/src/lib/engine/Engine.ts`) owns the renderer, scene, camera and rAF loop.
  Svelte talks to it through `engineRef.current` methods.
- **State**: `lib/state/editor.svelte.ts` holds Svelte 5 runes (`editor`, `stats`, `ui`). The engine
  *reads* `editor.*` each frame. **Never write per-frame data into reactive state.** `stats` is
  throttled to 2 Hz for this reason.
- **Terrain** (`lib/terrain/Terrain.ts`):
  - Heights are a `Float32Array` of `(size+1)^2` vertices; `CELL_SIZE` = 2 world units.
  - The mesh is split into 32×32-cell chunks. Edits call `markDirty(rect)`, and `update()` rewrites
    only the touched chunks.
  - Picking ray-marches the heightmap (`raycast`). Don't use triangle raycasts on the terrain.
- **Splat**: 8 layers in two RGBA8 textures (`splatA` = layers 0–3, `splatB` = layers 4–7) at
  `size*2` resolution. Weights always sum to 255 (`paintPixel` in `tools/brush.ts`). Layer list:
  `lib/terrain/layers.ts`; textures are procedural (`lib/terrain/textures.ts`).
- **Shaders** are custom `ShaderMaterial`s (terrain, water, sky). They include three's fog,
  tonemapping and colorspace chunks. Prop lighting (Hemisphere + Directional, intensities ×π) is
  tuned to match the terrain shader's uniforms. Change both together.
- **Tools** implement `Tool` (`lib/tools/Tool.ts`):
  - LMB goes to the active tool; RMB and MMB belong to the camera.
  - `tick(dt)` runs every frame while the button is held, so scale effects by `dt`.
  - Terrain brush tools extend `BrushTool` and record undo through `TerrainStroke`, which stores only
    the dirty sub-rect.
  - Object tools push `Command`s (`addCommand`, `removeCommand`, `transformCommand`).
  - **Every edit must be undoable** through `History`.
- **Objects** (`lib/world/ObjectLayer.ts`):
  - One `InstancedMesh` per prefab type, so draw calls scale with the number of types, not
    instances.
  - Objects store `x, z, yOff, rotY, scale`. Y is always `terrain height + yOff`, re-snapped after
    sculpting.
- **Prefabs** (`lib/models/prefabs.ts`):
  - Built in code with `ModelBuilder`: merged primitives, vertex colors, flat shading, optional
    vertex jitter. This is the chunky hand-made WoW look.
  - To add one, write a builder function and add an entry to `PREFABS`. The id is saved in map
    files, so never rename existing ids.

## WoW client assets

- Optional asset source: a user's **local** WoW 1.12 client. `internal/mpq` reads the archives
  (our own reader; `Gophercraft/mpq` is GPL, so don't add it). `internal/wow` decodes BLP, M2 and
  WMO files.
- `wow.Client.Handler()` serves `/wow/{status,list,texture,model}`. The handler is mounted via
  Wails `AssetServer.Middleware` in `main.go`, so it works in dev and prod. Responses are binary:
  - Textures: `"RGBA" w h pixels`.
  - Meshes: `Mesh.Encode()` = JSON header + pos/normal/uv/[color]/u32 index.
- **Never copy, bundle or commit Blizzard assets.** No extracted files in the repo, the binary or
  test fixtures. Map files store only paths (`m2:<path>` / `wmo:<path>` object types and
  `layerTextures`).
- The client path is persisted by `internal/config` (`os.UserConfigDir()/WorldEditor/config.json`).
- Coordinates: WoW model space is Z-up. `toEditor(x,y,z) = (x, z, -y)` is a proper rotation, so
  triangle winding is unchanged. 1 world unit ≈ 1 yard.
- Frontend: `lib/models/assets.ts` is the registry for all placeable types.
  - `getAsset(type)` returns the asset immediately, or a placeholder while a WoW model loads.
  - `onAssetLoaded` lets `ObjectLayer` and the place-tool ghost swap the placeholder for the real
    mesh.
  - WoW meshes are one geometry with groups plus a material array, which keeps it at one
    `InstancedMesh` per type.
- Integration test: `WOW_DIR=/path/to/client go test ./internal/wow/ -v`.

## Conventions

- TypeScript strict, no `any` in committed code. Prettier-ish style: 2 spaces, single quotes, no
  semicolons.
- Svelte 5 runes only (`$state`, `$derived`, `$props`, `onclick=`). No legacy `export let` or
  `on:click`.
- UI styling: plain CSS with the tokens in `frontend/src/app.css` (dark editor theme). No UI
  framework dependency.
- Avoid per-frame allocations in hot paths (brush loops, `frame()`). Reuse vectors and buffers.
- The app ships asset-free (procedural textures and prefabs). WoW content is only ever read at
  runtime from the user's own install.

## Platform notes

- Linux/Wayland: `env_linux.go` sets `WEBKIT_DISABLE_DMABUF_RENDERER=1`. Without it, WebKitGTK
  crashes with "Error 71 (Protocol error)" on this KDE Wayland machine.
- Windows uses WebView2 (Chromium) and has no cgo requirement, so it cross-compiles from Linux.
